# Документация по проектной практике

## Назначение раздела

Папка `docs/` содержит документацию в формате Markdown, подготовленную в рамках проектной практики. Документы описывают проект **«Семья в фокусе»**, разработанный статический сайт, вариативную часть с Telegram-ботом (каталог под код зарезервирован в `src/telegram-bot/`), порядок развёртывания и хронологию выполненной работы.

Документация дополняет сайт из папки [`../site/`](../site/) и фиксирует технические решения, принятые в ходе практики. Структура раздела согласована с подходом, использованным в учебном репозитории [practice_2026/docs](https://github.com/Godzol/practice_2026/tree/main/docs).

## Состав документации

- [`project.md`](project.md) — общее описание проекта «Семья в фокусе», идея, целевая аудитория и направления контента.
- [`site.md`](site.md) — архитектура, структура файлов, страницы и оформление статического сайта.
- [`telegram_bot.md`](telegram_bot.md) — назначение вариативной части (Telegram-бот), планируемое поведение и конфигурация.
- [`deployment.md`](deployment.md) — публикация через GitHub и хостинг-агрегатор (статический хостинг), автодеплой по push и замечания по боту.
- [`practice_journal.md`](practice_journal.md) — хронология этапов практики.

## Краткое содержание выполненной работы

Подготовлен статический сайт проекта «Семья в фокусе» в каталоге `site/`. Реализованы главная страница с блоком направлений («Что мы делаем»), раздел «О проекте» (`about.html`), страница участников (`team.html`), журнал с шестью материалами-карточками (`blog.html`) и страница ресурсов с акцентом на сообщество ВКонтакте и тематические подборки (`resources.html`). Стили и разметка оформлены в каждом HTML-файле; каталоги `site/css/`, `site/js/`, `site/images/` выделены под дальнейшее вынесение ресурсов.

В качестве вариативной части подготовлена проектная позиция и структура каталога `src/telegram-bot/`; реализация бота (зависимости, код, деплой процесса) при необходимости дополняется отдельным коммитом по методичке практики.

## Связь с требованиями практики

Типичные требования проектной практики включают:

- оформление материалов в Markdown;
- создание статического сайта;
- наличие разделов с описанием проекта, участниками, журналом и ресурсами;
- выполнение вариативной части;
- размещение результатов в согласованной структуре репозитория.

Текущая структура репозитория содержит Markdown-документацию в `docs/`, сайт в `site/` и заготовку под код бота в `src/telegram-bot/`. Итоговые отчёты в форматах DOCX/PDF оформляются отдельно при сдаче в LMS, по аналогии с завершением документирования в [practice_2026](https://github.com/Godzol/practice_2026).
