# Журнал выполнения практики

## Назначение

Документ фиксирует основные этапы работы над материалами проектной практики по проекту **«Семья в фокусе»**. Хронология отражает формирование структуры репозитория, создание статического сайта, подготовку документации и реализацию вариативной части (Telegram-бот).

## Этап 1. Изучение требований

Изучены требования к практике: статический сайт, разделы (главная, о проекте, участники, журнал, ресурсы), оформление в Markdown, вариативная часть, согласованная структура репозитория.

Выбрана целевая схема каталогов:

```text
/
├── README.md
├── docs/
├── site/
├── src/
│   └── telegram-bot/
└── .gitignore
```

## Этап 2. Концепция проекта и контент

Определена тематика проекта «Семья в фокусе»: традиции, совместный досуг, рецепты, книги и кино, истории семей, советы экспертов. Согласованы формулировки миссии и перечень рубрик для главной страницы и раздела «О проекте».

## Этап 3. Проектирование сайта

Запланированы страницы: `index.html`, `about.html`, `team.html`, журнал как `blog.html`, `resources.html`. Принято решение использовать единый визуальный стиль (светлая тема, карточки, фиксированная навигация), общую таблицу стилей и лёгкий JS по образцу [practice_2026](https://github.com/Godzol/practice_2026/tree/main).

## Этап 4. Реализация статических страниц

Созданы и наполнены страницы в `site/`:

- главная с hero-блоком и шестью направлениями («Что мы делаем»);
- «О проекте» с миссией и блоками преимуществ;
- «Участники» с шестью карточками ролей;
- «Журнал» (`blog.html`) — шесть публикаций-карточек;
- «Ресурсы» — карточки с соцсетями и тематическими разделами, рабочая ссылка на группу ВКонтакте.

Единое меню на всех страницах; файл журнала переименован из `journal.html` в `blog.html` для соответствия рекомендуемой структуре репозитория.

## Этап 5. Стили, скрипты и активы сайта

Стили собраны в [`site/css/style.css`](../site/css/style.css) и подключаются с каждой HTML-страницы; фоны hero блоков задаются модификаторами классов в CSS. Добавлен [`site/js/main.js`](../site/js/main.js): подстановка текущего года в элемент `#footer-year` в подвале. Каталог `site/images/` оставлен для локальных ресурсов. Корневой `README.md` и дерево документации приведены в соответствие с видом учебного репозитория practice_2026.

## Этап 6. Документация в Markdown

Подготовлены файлы в `docs/`:

- общий `[README.md](README.md)` раздела с назначением и связью с требованиями;
- `[project.md](project.md)` — описание проекта;
- `[site.md](site.md)` — архитектура и страницы сайта;
- `[telegram_bot.md](telegram_bot.md)` — вариативная часть;
- `[deployment.md](deployment.md)` — развёртывание;
- `[practice_journal.md](practice_journal.md)` — текущий журнал этапов.

## Этап 7. Вариативная часть (Telegram-бот)

Реализован Telegram-бот в каталоге `src/telegram-bot/`. Выполнена базовая настройка конфигурации и локальная проверка пользовательских сценариев (стартовая команда, справка, обработка запросов пользователя). Описание логики, запуска и конфигурации зафиксировано в [`telegram_bot.md`](telegram_bot.md).

## Этап 8. Развёртывание (при наличии площадки)

Публикация содержимого `site/` через статический хостинг, подключённый к GitHub-репозиторию (см. [deployment.md](deployment.md)): в настройках агрегатора задаётся **корень сайта — каталог `site/`**, затем проверка HTTP 200 для главной и проход по всем пунктам меню.

## Текущий результат

На текущий момент выполнены:

- статический сайт в `site/` со всеми требуемыми разделами;
- структура репозитория (`docs/`, `site/`, `src/telegram-bot/`);
- Telegram-бот как вариативная часть практики;
- расширенная отчётная документация в Markdown.

Остаётся по методичке практики (при необходимости):

- выполнить фактическое развёртывание сайта на выбранной площадке и указать финальный URL в отчёте;
- оформить итоговые отчёты DOCX/PDF и приложения для LMS.
